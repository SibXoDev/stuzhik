Консольная версия ​

stuzhik-cli это Stuzhik без окна: серверы Minecraft из терминала, службой systemd или в контейнере. Это один файл без зависимостей для любого Linux на x86_64 и на ARM (aarch64: Raspberry Pi 4 и новее, ARM-серверы).

Данные у него те же, что у приложения с окном: сервер, созданный в окне, запускается из терминала, и наоборот.

Установка ​

Файлы для x86_64 и ARM и команды, которые их скачивают и ставят, на странице скачивания. Для ARM в именах стоит arm64 или aarch64 вместо amd64 и x86_64.

СистемаКак поставить
Debian, Ubuntu, Mintsudo apt install ./stuzhik-cli_*_amd64.deb
Fedora, RHEL, Alma, Rockysudo dnf install ./stuzhik-cli-*.x86_64.rpm
openSUSEsudo rpm -i ./stuzhik-cli-*.x86_64.rpm
Arch и любая другаяtar xzf stuzhik-cli-*-x86_64-linux.tar.gz, затем sudo install -m 0755 stuzhik-cli-*-x86_64-linux/stuzhik-cli /usr/local/bin/

Пакеты пока не подписаны: dnf предупредит «skipped OpenPGP checks», это ожидаемо. Сверить файлы можно по SHA256SUMS: sha256sum -c SHA256SUMS --ignore-missing.

Java для сервера лаунчер скачивает сам. Она собрана под glibc: на Alpine и других системах на musl нужен пакет gcompat или своя Java в настройках сборки.

Быстрый старт ​

bash
stuzhik-cli create "Мой сервер" --mc 1.21.1 --loader fabric --accept-eula
stuzhik-cli run "Мой сервер"

Консоль сервера открыта в этом же терминале: команды набираются как обычно. Ctrl+C останавливает сервер командой stop (мир сохраняется), второй Ctrl+C завершает его сразу.

Сборку можно назвать по id, по имени или по их началу.

Сервер из модпака ​

bash
stuzhik-cli create "Пак" --modpack ./pack.mrpack --accept-eula

Модпак берётся из файла (.mrpack, .zip CurseForge, .stzhk), по адресу на modrinth.com, как modrinth:<проект>[@<версия>] или curseforge:<id проекта>[@<id файла>]. Ставится сразу сервером, без клиентских файлов игры, а клиентские моды пака отключаются. Моды, про которые не удалось узнать, нужны ли они серверу, перечисляются в конце, чтобы их можно было проверить руками.

Обновить пак:

bash
stuzhik-cli update "Пак"

Сначала видно, что изменится: какие моды добавятся, обновятся и уйдут. Применяется после «да». Перед обновлением делается бэкап (--no-backup: без него), уже лежащие конфиги остаются (--overwrite-configs: заменить их конфигами пака), --to выбирает версию. Обновление на версию пака для другой версии игры делается только в окне: там у него есть откат.

Команды ​

КомандаЧто делает
list, info <сборка>сборки и подробности (--json для скриптов)
create <имя> --mc <версия> [--loader …] [--port] [--memory МБ] [--accept-eula]создать и установить сервер
create <имя> --modpack <пак>сервер из модпака
run <сборка>запустить в этом терминале
console <сборка>консоль сервера, который run держит в другом терминале или службой
tuiэкран в терминале: сборки, консоль сервера и его server.properties
update <сборка>обновить модпак сборки, с предпросмотром
backup <сборка>, backups <сборка>, restore <бэкап> [--worlds]бэкапы
eula <сборка> [--accept], props <сборка> [key=value…]EULA и server.properties
analyze <сборка или файл лога>разбор логов: проблемы и что делать
service <сборка> [--install] [--system]служба systemd
pathsгде лежат данные

Загрузчики: vanilla, fabric, quilt, forge, neoforge. Все команды и опции: stuzhik-cli --help.

Служба systemd ​

bash
stuzhik-cli service "Мой сервер" --install
systemctl --user daemon-reload
systemctl --user enable --now stuzhik-<имя>
loginctl enable-linger $USER

Точное имя службы печатает первая команда. enable-linger нужен, чтобы сервер работал без входа в систему; --system пишет системную службу (нужен root), она работает от имени текущего пользователя.

systemctl stop сохраняет мир: сервер получает stop, а не обрывается. Упавший сервер перезапускается сам, а ошибка настройки (например, не принята EULA) не перезапускается, чтобы служба не крутилась вхолостую.

Консоль работающей службы: stuzhik-cli console "Мой сервер": последние строки вывода, потом живые, и ваши команды уходят серверу. Ctrl+C только отключает консоль, сервер работает дальше.

Контейнер ​

Образ собирается из архива консольной версии, на Podman и на Docker одинаково. Данные сервера живут в томе stuzhik и переживают пересоздание контейнера.

Собрать образ из архива консольной версии:

bash
curl -fLOJ https://get.stuzhik.ru/linux/cli
tar xzf stuzhik-cli-*-x86_64-linux.tar.gz
cd stuzhik-cli-*-x86_64-linux
cat > Containerfile <<'EOF'
FROM docker.io/library/debian:13-slim
RUN apt-get update \
 && apt-get install -y --no-install-recommends ca-certificates \
 && rm -rf /var/lib/apt/lists/* \
 && useradd --system --uid 10001 --user-group --home-dir /data --create-home stuzhik
COPY stuzhik-cli /usr/local/bin/stuzhik-cli
USER stuzhik
ENV STUZHIK_DATA=/data
VOLUME ["/data"]
EXPOSE 25565
STOPSIGNAL SIGTERM
ENTRYPOINT ["/usr/local/bin/stuzhik-cli"]
CMD ["list"]
EOF
podman build -f Containerfile -t stuzhik-cli .

Создать сервер и запустить его в фоне, затем подключиться к консоли:

bash
podman run --rm -it -v stuzhik:/data stuzhik-cli create "Мой сервер" --mc 1.21.1 --loader fabric --accept-eula
podman run -dit --name mc -v stuzhik:/data -p 25565:25565 --stop-timeout 120 stuzhik-cli run "Мой сервер"
podman attach mc

Отключиться от консоли и оставить сервер работать: Ctrl+P, затем Ctrl+Q. stop (или podman stop mc, docker stop mc) сохраняет мир: на это контейнеру дано 120 секунд.

Данные ​

По умолчанию это та же папка, что у приложения с окном. Другая: --data-dir /srv/stuzhik или переменная STUZHIK_DATA=/srv/stuzhik.

Пока команда работает, окно не переносит папку данных на другой диск и говорит почему, а команда, запущенная посреди переноса, ждать не станет и попросит дождаться его конца.

Язык и коды выхода ​

Сообщения выводятся на языке системы; STUZHIK_LANG=ru или en задают его явно (у сервера часто стоит C, тогда русский).

Коды выхода: 0: готово, 1: сервер упал, 2: отказ (сборки нет, EULA не принята, неверная опция), 3: analyze нашёл критичную проблему. На них опирается служба: код 2 не перезапускается.
