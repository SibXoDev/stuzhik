On this page

Mods ​

A build's mods are on the «Mods» tab of its page. At the top are two modes: «Installed» and «Catalog».

Catalog ​

Search over Modrinth and CurseForge, already narrowed to the build's game version and loader; «Show incompatible» lifts that filter. «Categories» narrow the search, «Add to favorites» keeps a mod for later. A list or tiles is picked with a button in the catalog's toolbar and remembered for every catalog.

«Install» takes the version for the build: the one that fits next to the mods already installed. While a mod installs, its card shows «Picking a version…» and «Downloading · N%», the cross «Cancel install» stops it. Everything being installed into the build also shows on the «Installed» side, as an «Installing» block above the list.

A mod comes with only its own dependencies. Missing dependencies of mods you did not touch are installed apart, with «Install all missing» on the «Dependencies» tab.

Your own .jar can be dropped onto the window or added with «Add local mod (.jar file)».

The mod card ​

A click on a mod opens its card: the description, every version and the dependencies.

  • Changing the version: pick a version right in the list, no need to remove and reinstall. «Hide incompatible» drops the versions that will not fit this game and loader
  • The graph: what depends on what and what conflicts with what

The mod list ​

  • Turn on and off: the switch in the row; a disabled mod stays as .jar.disabled and does not load
  • Updates: the button above the list checks for new versions for this build and shows what will update. If a download fails, the old file stays
  • Pin the version: the pin in the row or the item in the right-click menu. Updates, auto-update and a modpack update leave a pinned version alone
  • Auto-update: the icon in a mod's row: a found update installs by itself when updates are checked. Whether new mods get it is decided in «Settings → Mods»
  • Delete: in the mod's menu; several mods: select them and delete at once. Before deleting you see what depends on it

Changes show at once, wherever they happen: a mod disabled in the log analysis, updated by a modpack or dropped into the folder as a file appears in the list without a reload.

Dependencies and conflicts ​

The «Dependencies» tab gathers everything in the build's way:

  • Missing dependencies and wrong versions: «Install all missing» installs them with one button
  • Incompatible pairs: mods that do not work together
  • «Not for this build»: a mod for another game version or another loader («AppleSkin for Minecraft 1.21.11, but the build is on 1.21.1»), with a «Disable» button. The pre-launch check shows the same

The graph shows this as a picture. From a mod's panel in the graph you can disable or delete it (with the same «what will break» window), and install a missing dependency with the button next to it: only it and what it needs itself are installed. The nodes stay where they are.

Overlaps ​

The «Overlaps» tab in «Dependencies» reads the jar files of the enabled mods, running nothing, and shows where mods step on each other's toes:

  • Mixin clashes: two mods replace the same game method whole or redirect the same call, so one change will not apply
  • The same game methods: several mods change one method. Usually that works, but if the game crashes there, start with them. On Fabric and Quilt methods carry readable names (PalettedContainer.acquire, not class_2841.method_12334)
  • One craft, different items: two mods give different items for the same ingredients, and the game takes only one recipe. You see the crafting grid or the furnace with icons and every result variant. KubeJS, CraftTweaker or Polymorph in the build are taken into account
  • Same materials and ore generated twice: tin, steel, lead from several mods
  • Libraries at different versions: mods embed one library, the loader keeps one

«Copy report» gives all of it as text, to send to a mod's or a modpack's author.

Built-in update checks ​

Mod Menu, Iris, Distant Horizons, Forge and NeoForge can announce new versions at every start by themselves, and Distant Horizons can download its update on its own. The launcher turns this off by default: it handles mod updates. The switch is in «Settings → Mods → Mod integrations». One build can have its own choice in «Edit», and which builds do not follow the common setting shows in «Settings → Launch → Per-build settings».

Performance ​

The «Performance» tab (under «More» on the build page) shows memory and CPU while the game runs. With the Spark mod it also shows what each mod costs («Impact»), bottlenecks and recommendations. Spark installs with a button there.

Where the mods are ​

In the build's folder: mods inside instances/<build> of the launcher's data folder. Where that is and how to move it: Builds → Where the data is.

If something is wrong ​

A mod does not show up in the game. Look at the «Dependencies» tab: the mod may be «Not for this build» (another game version or loader), or it lacks a dependency. And check that it is enabled.

The game crashed after installing a mod. The Log Analyzer names the culprit and offers to update or disable it. To go back to the previous version: the mod's card, the version list.

A mod does not update. Its version may be pinned (the pin in the row), or there is no new version for your game version yet.
