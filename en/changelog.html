Changelog ​

What changed in each version of Stuzhik. Search by words and narrow the list by kind and mark — say, fixes only or experimental features only; the versions are listed under “On this page”. The same list is in the launcher — the “Versions” window → “What's new”: the “Changelog” icon in Settings, the “Changelog” button in Documentation, the version cards in the news panel and Ctrl+K → “Versions”. It is also an RSS/Atom feed: subscribe in your favorite feed reader (Feedly, Inoreader, your browser's built-in reader), and news about new versions will come to you on its own.

How to read a version number: the middle number is a stage, a big release with new things; the last one is a patch to it, fixes. Releases are numbered this way from 0.1.0 on; before it the numbers ran in a row, and the patches of that time are marked “Patch”.

Stuzhik 0.0.19

1613332October 20, 2026
  • SecurityBeta“Friends” runs on a new connection, and all of it is encrypted: files, a build's file list, its name, nicknames and permission prompts. Before, the start of a connection went in plain text and showed your identifier and nickname — now it is QUIC with TLS 1.3 instead of the old TCP and home-made cipher. Everything goes over UDP on two ports, and the Windows firewall rule is now a single one, “Stuzhik Connect”. Launchers 0.0.18 and older can't connect at all: instead of a long wait the launcher says right away that your friend has a different Stuzhik version, and “Friends” shows that an older Stuzhik is nearby
  • User agreement version 3: section 3 now says that your own answer next to “Other” in “How did you hear about Stuzhik?” is sent once, with the first report. If you accepted an earlier version, at launch you see the changed places highlighted (added in green, removed struck through), the text and two buttons — “Decline and quit” and “I accept”; your statistics choice and your earlier answer are kept. Until you answer, no statistics are sent. The agreement opened from settings now has a “Version history”
  • The “Changelog” window became “Versions” with three tabs: “What's new”, “Roadmap” — Stuzhik's path along an ice trail: finished stages, the current one and plans, each with what went into it and in which releases — and “Known issues”: what doesn't work yet and how to get around it
  • The “Builder” became a full build editor. “Contents” is a table like a build's mod list: a row opens the mod card, a mod can be turned off, and sizes are shown. “Catalog” is the same as in the “Mod Collections” section, already set to the project's game version and loader. “Compatibility” checks the contents without installing anything — what is missing and what won't work together, including limits declared inside the jars — and draws a “Dependency graph”. “Configs” holds the project's configs with highlighting, edit history, diffs and restore, search and “Open in VS Code”; they go into the .stzhk export and into a build created from the project, and importing a .mrpack takes them from the archive
  • “Pin the version” for a Modrinth or CurseForge mod — with the pin button in its row or from the mod menu: update checks, auto-update, manual updates and modpack updates leave it alone. Changing the version by hand keeps the pin
  • YouTube videos in mod and modpack descriptions now play right in the launcher — before, they were cut out entirely. First a preview with the title, then on click the real YouTube player with chapters, subtitles and speed; “Open in browser” and “Copy link” are always there and continue from the current second. Timestamps in the description (“1:35 Installation”) and links to the same video seek the player
  • A “Check for updates” button in Settings → General → “App Updates”: it checks the selected channel right now and installs a found version with a restart, asking first if a server is running or something is downloading. “No updates” and “Could not check” are different answers: an error is never passed off as the latest version. Before, the launcher checked for updates only at startup
  • Picture background: “Picture position” — “Fill”, “Fit”, “Stretch”, “Center” or “Tile” — and “Picture blur” (Settings → Interface). With “Fit”, the empty edges are filled with a blurred copy of the picture instead of black
  • “How did you hear about Stuzhik?” now has a “Your own answer” field next to “Other” — up to 40 characters. It is sent once, with the first report; anything that looks like a contact (email, link, phone number) is never sent, and the window warns you right away. If your first report has already gone, the field in Settings → Privacy is disabled — there is nowhere left to send it
  • BetaFriends behind a VPN without a shared network — Tailscale and the like: you only need to add a friend by address once. After that the launcher remembers their address, knocks on it at startup and every 5 minutes and keeps them online, and rooms, profile style and what they are playing reach you the same way as on a local network. A person's card has a new “Check connection” button: a check on every known address with the outcome — response time, “no answer”, “different Stuzhik version” or “you are hidden from them” — and the kind of network: local, Tailscale, Radmin VPN, Hamachi or the internet
  • Beta“Hide from this friend” in a friend's menu: to them you are offline — they see neither you nor your builds or rooms, and the launcher doesn't connect to them on its own. Fully within 15 minutes. The list and the way back are in Settings → Connect
  • BetaTwo new privacy settings in Settings → Connect: “Who sees my profile style” — everyone or friends only, and “Accept friend requests” — when it is off, requests are silently dropped
  • BetaProfile style: “Banner colour” fills the header without an effect or colours the effect itself; the avatar's “Behind the picture” is your own colour or “Transparent”, so a cut-out picture sits right on the card; “Frames” for the avatar and the whole card — line, double, glow, gradient and animated ones: running light, pulse, rainbow. The card's “Accent” now also tints highlights and soft fills inside it, not just the buttons
  • BetaA request to take an unpublished build can now be allowed for one person: “Allow for a day” in the “Inbox” opens it to them only and only for a day, with no second question. Before, the only option was “Open to friends” — to everyone and for good. The person asking now sees that the request went to the owner and that they can press “Take” again
  • ExperimentalCo-op build — a full-screen editor: the contents as a table with search, filters and a “new” mark since your last visit, who added each mod and when, and the build's size. “Catalog” is the same as in the “Mod Collections” section, set to the room's version and loader; a mod's name opens its card. Resource packs and shaders are part of the contents, and mods can be turned off and their versions pinned. The “Compatibility” tab marks missing dependencies and conflicts right in the contents, and everyone sees the “Dependency graph”, even without their own copy of the build. The host can add a “Room description”
  • ExperimentalCo-op build: a “Configs” tab — view with highlighting, edit (Ctrl+S), upload your own files, create folders, search by content. Every edit has a git-style diff and a restore to the previous state, deleted files included; “Open in VS Code” saves straight into the room. A file open on two machines updates in place, and if you have unsaved edits you can compare and choose. Configs changed on the host's disk outside the launcher (by the game, in a text editor) reach the room too. Only friends with the right role see configs: they can contain tokens
  • ExperimentalCo-op build: roles — “Editor”, “Member”, “Viewer” — with permissions, per person and for newcomers. “Who can join” is chosen when the room is created, “Friends” by default (before, anyone who could see the host walked in), and only those who may join see the room; there is invitation-only entry and “Remove from the room”. Reactions were replaced by a discussion of the room and of a single mod or config, with flood protection and “Mute in the discussion”. A mod can be “Put to a vote” — the host decides; you can withdraw your own proposal until it is decided, and an edit in the feed can be undone. “Get the pack” by a member now asks the host; silently only with the “Take the build without asking” permission
  • ExperimentalCo-op build without installing: “Build together” → “Without installing” or “From the Builder” — the room lives on a Builder project and downloads nothing. Everyone installs their own copy (“Install for me”, “Update my copy”), and the copy follows the host's loader version by itself. “Pin the room” brings it back by itself after the host restarts; “My own room based on this one” and “Continue on my own” while the host is away work only if the host granted “Copy the room”

Dependencies are picked the same way, and the preview shows the dependencies of exactly the version that will be installed. The same applies to collections from the “Mod Collections” section and to the “Builder”. Modrinth mods only for now
  • A mod install from the catalog can be cancelled while it runs: the card and the recommendations show its stage — “Picking a version…”, “Downloading · N%”, “Dependencies…” — with a cancel button, and an “Installing” block appears above the build's mod table. Before, the status froze until the end and there was no way to stop it. A cancel isn't shown as an error, and optional dependencies you picked are not installed after it; if the mod had already downloaded, it stays in the build and the launcher says so. A failed install says what went wrong instead of staying silent
  • The build install window and the install block on the build's page showed a card for every file being downloaded — hundreds of “Asset …” rows. Now it is one line: “Files downloaded: N”, the current file and the total speed — and only this build's files (before, the build page showed every download in the launcher). The install step no longer falls back to “Java” while Minecraft is downloading
  • A colour picker of our own instead of the system dialog: a saturation and brightness square, a hue strip and a field where you can paste #hex, rgb(), hsl(), “30, 144, 255” or a colour name; a HEX/RGB/HSL switch, preset colours and a screen eyedropper where the system provides one. It works in “Create theme”, in the “Custom color” of the accent and the animated background, and in your profile style. The Windows system dialog didn't even have a hex field
  • Images in mod descriptions no longer silently go missing — before, almost half of them didn't show. Images from large platforms — GitHub, imgur, Discord, badges, YouTube previews and others — load at once, and from other sites by a “Show” or “Always show from this site” button (the list is in Settings → Privacy): such a site learns your IP address. Hosting ads are hidden. Buttons in a description (“How to install”, Discord…) sit in a row as on Modrinth, and the gallery viewer shows the original instead of a stretched 350-pixel preview
  • Fonts are built into the launcher: it no longer contacts Google Fonts at every start — nothing ever loaded from there anyway. The monospace font in logs, the console and the editor is Cascadia Mono (on Windows it used to fall back to Consolas), without ligatures: “!=” stays “!=”
  • Uninstalling the launcher cleans up after itself: cache, logs, error reports and the built-in browser's data are always removed, and so are saved account logins (in the Windows Credential Manager) and the firewall rule. The checkbox now says what it does — “Also delete builds and worlds (all launcher data)”: nobody ticked it before, so everything stayed behind. An update, or installing a new version over the old one, touches none of this
  • The update check at startup no longer waits for a silent server: the next address is asked after a second and a half instead of after a timeout, and while the Stuzhik server answers, GitHub isn't asked at all. And if the connection goes silent while the next update is downloading, after 30 seconds it counts as a drop — before, the download window hung forever and the launcher didn't start
  • A mod in a build's mod list has a right-click menu with the same actions as its buttons plus “Open the mod page”. Row buttons no longer hide until you hover (build groups, Builder projects, the inbox). The authors line no longer eats the mod's name (Iris lost it entirely), and in a narrow window the mod table hides the “Side” and “Size” columns
  • BetaTransferring a build got several times faster, especially over a VPN: the launcher asks for the next files without waiting for the previous one to arrive — 600 small files at 40 ms latency arrive in about 3 seconds instead of 24 or more, and files no longer swell by half on the way. A build of more than 10,000 files (TerraFirmaGreg-Modern has 12,143) is no longer refused by the sender: the cap is now 100,000. And the “Friends” section no longer freezes while thousands of small files are transferring
  • BetaA transfer survives a connection drop of up to a minute and a half: the launcher waits for the friend to become reachable again and resumes from the same byte. The transfer history now shows why a transfer failed — before, it was blank
  • BetaFriends see changes at once: a room opened or closed, a game started or ended, a new profile style reach neighbours in a fraction of a second instead of 5–7 seconds, and turning Connect off or quitting the launcher shows within a third of a second instead of 20
  • Beta“Get the pack” now brings almost the whole build: along with mods, configs and resource packs come CraftTweaker scripts, OpenLoader files, Patchouli books, Resource Loader resources and FancyMenu menus. The local/ folder stays behind on purpose: it holds each player's own mod data
  • ImportantRestoring a backup deleted worlds: the saves folder was replaced whole, a world created after the backup was lost for good, and the others were silently rolled back — even though the automatic backup before a mod update includes worlds by default. Now worlds are restored one by one, and a backup with worlds asks: “Without worlds” (the default) or “With worlds”. The “Backups” tab reports the result of every action (it used to stay silent, and a refusal while the game ran looked like success), “Restore” is disabled while the game runs, and a build's “Use global setting”, “Enabled” and “Disabled” buttons finally save — “Enabled” works even with global backups off
  • ImportantUpdating a mod or switching its version first deleted the mod and only then downloaded the new version — a network failure left the build without the mod. Now the old file is set aside and put back if the new version didn't install. A disabled mod stays disabled after an update (it used to turn itself on), and the “Updates” window no longer counts a mod that failed as updated and says which ones stayed as they were
  • ImportantEnabling a resource pack when options.txt couldn't be read (a different encoding, no access) rewrote the file from a single line — all game settings were lost. Now such a file is left alone, and writes are done so that an interruption can't leave half a file behind
  • ImportantBeta“Get the pack” overwrote your own build with the same name (and “Forge 1.20.1” is the default name): everything of yours that the owner didn't have was wiped. Now the launcher tells a copy taken from a friend apart from your own build: into your own build it only adds what is missing, and if that build has another game version or loader it refuses with an explanation; a running one it asks you to close. Also, the friend now gets the same loader version as the owner (a build created with the latest loader version didn't pass it on, and the friend got their own latest), the usual install window opens — Java, Minecraft, loader — cancelling the install keeps the files already received, and a broken build is repaired after “Take” instead of being reported as already complete
  • SecurityThe “Delete config” auto-fix takes the file name from a log line, and a server log also contains player chat: a message like “Exception reading config ops.json” became a fix that deleted ops.json, server.properties or the ban lists from the server root — and “Fix All Problems” ticks every fix at once. Now only files in config/ and defaultconfigs/ are deleted — that is also where the fix now looks for the config; before, it almost always answered that the file wasn't found
  • SecurityInstalling a .stzhk from a link took the temporary file name from the link itself, and a link containing “..%2F” could write the download outside the cache folder. Now each install gets its own file name, and the downloaded archive is removed even after a failed install (it used to stay in the cache). Two installs from Google Drive links at the same time no longer write into the same file
  • SecurityBetaA build you took from another device could place files outside the build's folders — for example into versions/ next to the game, even before the loader was installed.
